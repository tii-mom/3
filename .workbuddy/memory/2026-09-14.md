## #79 人民币返点余额抵扣商城订单（本日主体）
### 数据层
- 迁移 `213_shop_wallet_deduction.sql`：`shop_orders` 加 `wallet_applied_cny_minor`、`payable_cny_minor`（默认 0）；
  存量回填 `payable = snapshot_price`（带 `wallet_applied=0 AND payable=0 AND price>0` 三条 WHERE，重复执行无副作用）；
  加两条 CHECK：抵扣额 `>=0 且 <= 价格`、恒等式 `payable = price - wallet_applied`。
- **关键不变量**：`payable_cny_minor = snapshot_price_cny_minor - wallet_applied_cny_minor`。
  任何 INSERT 进 `shop_orders` 都必须显式写 `payable_cny_minor`，否则默认 0 会**直接触发 CHECK 报错**。
  ⚠️ 本日踩到：`shop_guest_service.go` 的免登录下单 INSERT 漏了这列 → 游客买任何商品都会失败，已补 `$7`。

### 资金语义（核心决策）
- 返佣基数 = **外部实付金额 `payable_cny_minor`**，不是商品原价。
  用余额抵扣掉的那部分是平台已经付过的返点，再计一次就是「返点 → 抵扣下单 → 再返点」的无锚增发。
  ⇒ **全额抵扣的订单不产生任何返佣**（`issueCommissionTx` 里 `baseMinor <= 0` → `commission_status='none'`）。
- 服务端 `shop_service.go`：
  - `CreateOrderAndPayment(..., useWallet bool)`：`payableMinor <= 0` → 走 `FulfillWalletPaidOrder`（无外部支付单，直接交付）；
    否则建支付单。支付单创建失败 → `abortPendingShopOrder` 作废订单并**退回抵扣**。
  - `createPendingShopOrder`：先落单（`payable = price`）再抵扣，抵扣流水需要订单号做幂等键；
    `debitWalletForShopOrderTx` 用 `FOR UPDATE` 锁钱包行、按 `min(可用, 应付)` 抵扣、写 `distribution_wallet_ledger`
    （action `shop_wallet_deduction`，idempotency_key `shop:order:{id}:wallet-deduction`）。
  - `refundShopOrderWalletTx`：订单取消/超时/失败时退回，幂等键 `shop:order:{id}:wallet-refund`。
  - `WalletBalance`：返回 `{enabled, available_cny_minor, frozen_cny_minor}`，推广计划未启用 → `enabled=false`（前端不显示抵扣入口）。
  - `fulfillShopOrder(paymentOrderID, shopOrderID)`：二选一定位订单；`paymentOrderID<=0` 表示无外部支付单，
    `completeLinkedPaymentOrder` **只写不提交**，由调用方统一 Commit。
- ⚠️ 本日踩到并修掉：`completeLinkedPaymentOrder` 原本内部 `tx.Commit()`，主链路又 Commit 一次 → 双提交 `sql.ErrTxDone`。已改为不提交 + 两个早退分支显式 Commit。
- ⚠️ 本日踩到并修掉：全额抵扣订单若交付失败（库存被并发抢空）会「余额已扣、货没发」→ 现在失败即 `abortPendingShopOrder` 退回。
- Handler/路由：`POST /shop/orders` 增加 `use_wallet`；`payment_type` 由 `binding:"required"` 放开为可选
  （全额抵扣没有支付环节），是否必填改由 service 按应付金额判断。
  新增 `GET /shop/wallet-balance`。
- 列表：订单列表 SELECT + `scanShopOrder` 补上 `wallet_applied_cny_minor` / `payable_cny_minor`（前端要展示抵扣明细）。
