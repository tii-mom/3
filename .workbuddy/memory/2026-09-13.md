## 算力公司重构调研 + 三套方案（仅分析，未改代码）

用户要求：先看算力公司代码 → 以黄峥视角给重构建议 → 以商城（GPT 代充 + 成品号）为主 → 出 3 套方案并说哪个最优 → **确认后才动代码**。

### 代码事实（已核实）
- 算力公司 = `compute_company`，5 层 + 3 档（`177_distribution_program.sql`）：
  T1≥¥1000 → 10/4/3/2/1（20%）、T2≥¥100万 → 15/6/4/3/2（30%）、T3≥¥1000万 → 20/8/6/4/2（40%）；首充额外 10%。
- **触发路径只有 API 余额充值**：`payment_fulfillment.go` `doBalance` → `applyDistributionForOrder` → `distribution_service.go` `ProcessRecharge`（L421）。
- **商城返利是独立的单层表**：`shop_service.go` `issueCommissionTx`（L682），只发直接邀请人，`商品价 × snapshot_commission_bps ÷ 10000`。
- 线上 12 个 SKU 实测佣金 1%–10%（X 蓝V 10%、GPT Plus/成品号 5%、GPT20刀 3%、拼车 2%、GPT100刀 1%），加权约 3.8%。
- **两轨共用同一个 `distribution_cash_wallets`**（program 都是 compute_company），共用冻结与支付宝提现（最低 ¥100）。→ 钱包视图需按 ledger `source_type` 拆分。

### 三处硬伤
1. 成本倒挂：现货货毛利薄，T1 档就要拨 20%，照搬到商城 = 卖一单亏一单（只有预付款型 API 充值扛得住）。
2. 激励方向相反：算力公司奖"拉宽升档吃深层"，商城只奖"直接成交一次"。
3. 一句话讲不清。

### 三套方案
- **A 解耦（推荐）**：商城 = 一级推荐 + 拼车团内生裂变（主推品佣金提到 12–15%、长尾压 3–5%）；算力公司参数不动但只服务 API 充值、对纯商城用户不展示入口；钱包按来源标签拆分视图。→ 迁移成本近零（商城代码本就只发一级）、复用关系链、老用户即首批推广者。
- **B 微调**：算力公司压到 3 层、拨出降到 10/15/20；商城佣金提到 8–15%。→ 三个问题一个没解，还留技术债。
- **C 聚焦**：算力公司 `enabled=false`（历史佣金照发、关系链保留），商城做一级 10% + 拼车团 + 冲榜。→ 最干净但砍掉 API 引擎。

### 结论
推荐 **A**；唯一会推翻 A 的条件 = 若 API 彻底降级为引流、商城是全部未来 → 改推 C。
待用户定的三个数：主推品佣金上限（建议 ≤ 毛利 40%，需渠道成本）、拼车团团长奖励（建议 3–5%，成团才发）、北极星指标 = 商城月度去重成交用户数。
