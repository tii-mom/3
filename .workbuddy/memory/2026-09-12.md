### 6) 「无法下单支付」根因 + 统一
- 根因：首页下单 `return_url` 传的是 `/shop`（登录态）或 `/order`（游客），
  而后端 `CanonicalizeReturnURL` **只接受 path === `/payment/result`** → 被拒 → 下单失败。
- 修：`useGuestCheckout.ts` 新增 `buildReturnURL()` → `window.location.origin + '/payment/result'`（登录/游客两路都用）；
  与控制台 `ShopView` 的 `\${origin}/payment/result` 完全一致。
- 同时砍掉前端 `GUEST_METHOD_WHITELIST = ['alipay','wxpay','easypay']` 硬编码白名单 → 改用与后台同源的
  `getVisibleMethods(limits)`（后台只开 stripe 时首页不再显示「暂无可用支付方式」）。
- `getVisibleMethods` 改泛型 `getVisibleMethods<T>`：控制台的 `MethodLimit` 与首页精简的 `PublicPaymentMethod` 共用归并规则、类型互不污染。
- 补上 `decidePaymentLaunch` 的 `stripeRouteUrl`/`airwallexRouteUrl`（`router.resolve` 构造），
  并新增 `stripe_route`/`airwallex_route` 分支直接 `window.location.href` 跳转（不留在抽屉后面）。

### 🔴 P0（代码 bug，必修）
1. **未知路径被踢到登录页，看不到 404 页。**
   `router/index.ts:932` `const requiresAuth = to.meta.requiresAuth !== false`（默认 true），
   而 404 catch-all（`/pathMatch`）的 meta 没写 `requiresAuth:false` → 未登录访问任意无效 URL
   → `next({path:'/login', query:{redirect}})`。`/typo` 实测 title=`Login`、h1=`3API`。
   影响：外投错链/手输错址全部流失，且软 404（大量 URL 返回登录页 200）不利 SEO。
   修：`NotFound` 路由 meta 加 `requiresAuth:false`。
2. **首页运行时 title/description 是过时的「AI API 中转站」文案。**
   `seo.ts:5` `DEFAULT_TITLE='3API - AI API 中转站与多模型统一接入'`，
   `updateRouteSeo`（`App.vue:29` 调用）对 `/` 回退到 DEFAULT_TITLE —— 覆盖了守卫里设的正确标题。
   构建期 `check-built-seo.mjs` 只断言**预渲染 HTML** 的 title（是对的），但运行时会**被 JS 覆盖**，
   所以 bug 漏过了 CI。实测运行时 title/og:title/description 全是中转站文案，og:image/canonical 正确。
   修：`seo.ts` 给首页单独的 `HOME_TITLE`/`HOME_DESCRIPTION`（与 SEO 文案一致），或 `/` 路由补 `seoKey`。

### 🔴 P0（业务/合规，需决策或改文案）
