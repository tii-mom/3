  - `build-and-push`：`if: event_name == 'push'` → 只构建镜像推 GHCR，**不部署**
  - `deploy-to-vps`：`if: event_name == 'workflow_dispatch'` + `environment: production` → 手动部署后端
- `production-preflight.yml`：手动 dispatch，做生产 DB 备份 + 隔离恢复验证，
  需 `-f image_digest=sha256:... -f confirmation=BACKUP_AND_RESTORE_ONLY`

### ⚠️ 部署顺序陷阱（务必遵守）
前端首页**强依赖** `/public/shop/products`、`/public/shop/banners`。
若一次性 push（前后端一起），新首页立即上线但后端还是旧的 → **首页商品区直接挂**。
**正确顺序**：
1. 只提交并 push `backend/`（不触发 pages-deploy，因为 paths 只监听 frontend/**）
2. CI 通过后手动 dispatch 部署后端到 VPS
3. 再提交并 push `frontend/`（此时后端已就位，前端无缝上线）
注意：不能在同一个 commit 链里做——merge commit 的父链会带上前端 commit，
一次 push 必然把前端也推上去。所以要 `git reset --soft origin/main` 后**分两次 commit + 分两次 push**。

- **218svh 首屏不能抄**：我们是交易页，首屏太高会把商品推到折叠线下，直接掉转化
